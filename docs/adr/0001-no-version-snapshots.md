# 技能不存版本事实，只存结构规则与查证路径

技能里**不出现任何「当前版本是什么」的陈述**：

- 不写当前版本号
- 不写版本-版本兼容对照表
- 不写「最新是 x.y.z」
- 不写具体弃用日期

允许保留的只有两类：

1. **结构规则**——不依赖具体版本号也成立的判断。例如「大版本换代常伴随破坏性变更」「`latest` 标签可能指向预发布」「框架内置 canary 版本可能与项目安装版本不同」。
2. **查证路径**——具体到命令或 URL。例如 `npm view <pkg> dist-tags`、官方支持矩阵页地址。

允许的例外：**行为分界线**可以带版本标识，因为它是判断「新旧 API 世代」的锚点。例如「SQLAlchemy 从 2.0 起提供 async 支持」。这类必须同时给出官方来源，并在措辞上表明它是分界不是现值。

原因：技术栈持续更新，写死版本会让技能本身变成需要跟进的负担。维护一个必然过期的版本表，成本高于每次现查。而且错误的版本号比没有版本号更贵——读者会当真。

代价：每次选型都要现场跑命令；读者拿不到「开箱即用的版本答案」。这是有意接受的。
