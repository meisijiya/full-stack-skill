# 组合约束分两层：技术硬约束与生态惯例

技能里的组合约束分两层，判定标准是「有没有官方文档能证实」：

- **技术硬约束**：官方文档明确说明不兼容、有版本耦合或平台限制。每条附官方原文与 URL。
- **生态惯例**：某个框架、脚手架或社区的常见搭配，不是不可逾越的限制。附说明，不附「硬约束」标签。

不把脚手架的集成矩阵当硬约束。参考对象 `vibestart` 的 19 条组合约束经逐条对官方文档审计后，多数属该脚手架的集成偏好而非技术不兼容（例如「MongoDB 只能用 Mongoose」与 Prisma 官方 MongoDB connector 文档相悖，「SQLite 只能用 Drizzle」与 Prisma 官方 SQLite connector 文档相悖）。把这类偏好标成硬约束，会诱导用户在需求变更时降级本可保留的能力。

原因：错误的硬约束比没有约束更贵——它让用户为一个本可以继续的功能付出降级代价。

代价：技能给出的候选组合比「穷举矩阵」少。需要靠「生态惯例」层补足实用信息，并明确标注其非强制性质。
